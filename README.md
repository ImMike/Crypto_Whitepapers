## What is this?

A snapshot of the crypto whitepaper landscape — **882 PDFs**, mostly from the **2016–2018 ICO boom**, the single largest wave of whitepaper publishing in history.

Most whitepaper "archives" are just a folder of PDFs. This one is **mined**: a small, dependency-free toolchain reads every PDF and extracts the metadata you actually want to query —

- 🧑‍💼 **Founders & team** — role-confirmed names (CEO, CTO, founder, advisor…)
- 💰 **Wallet & contract addresses** — ETH/EVM and Bitcoin addresses found in the text
- 🔗 **Social & community links** — Twitter/X, Telegram, Discord, GitHub, Reddit, Medium, LinkedIn…
- 📅 **Publication years** — inferred from each document

…all dumped into [`data/whitepapers.json`](data/whitepapers.json) and [`data/whitepapers.csv`](data/whitepapers.csv) so you can grep, query, and analyze the whole ICO era in seconds.

> 🔬 **Why it's useful:** researchers studying ICO-era fraud, journalists tracing teams across projects, on-chain analysts mapping addresses to projects, and anyone curious how 882 projects pitched themselves at the peak of the hype cycle.

## 🔎 Notable findings (from the extracted data)

Mining the archive surfaces things a folder of PDFs never could:

- **Recycled boilerplate.** *Augmentors* and *Billionaire Token* list the **same two Ethereum contract addresses** (`0x49aec0…17ed7`, `0x23EA01…3ff1`) — a fingerprint of a shared team or copy-pasted template.
- **Example addresses pasted as real ones.** Bitcoin's genesis address (`1A1zP1…DivfNa`, Satoshi's) and a well-known Ethereum whale wallet (`0xb794f5…579268`) appear across multiple unrelated whitepapers — a reminder to **always verify before sending anything anywhere.**
- **Repeat advisors.** A handful of names recur across many projects — e.g. *Michael Terpin* (4 papers), *David Drake* (3), *Vitalik Buterin* (3, mostly as a citation) — the small world of ICO-era advisory.

## 🚀 Quick start

```bash
git clone https://github.com/ImMike/Crypto_Whitepapers.git
cd Crypto_Whitepapers
```

**🔎 Search (no install):** the [**live search site**](https://immike.github.io/Crypto_Whitepapers/) filters all 882 papers by name, team, wallet address, social handle or year as you type.

**Full-text search, offline** ([`tools/search.py`](tools/search.py) — searches *inside* the papers):
```bash
python tools/search.py "proof of stake"     # full text of every whitepaper
python tools/search.py --wallet 0x49aec0     # which projects list this address
python tools/search.py --team Terpin         # find a person across the archive
python tools/search.py --social telegram --year 2017
```

**Full-text search on GitHub:** because each paper's text is committed under [`text/`](text/), [GitHub code search](https://github.com/search?q=repo%3AImMike%2FCrypto_Whitepapers&type=code) searches the whitepaper *contents* natively.

**Browse:** open [`data/INDEX.md`](data/INDEX.md) for a clickable A–Z table of all 882 papers with their metadata.

**Query the JSON** (needs [`jq`](https://jqlang.github.io/jq/)):
```bash
# Every paper that exposes an ETH/EVM address
jq -r '.[] | select(.wallets.eth_evm) | "\(.name): \(.wallets.eth_evm[0])"' data/whitepapers.json

# All papers with a Telegram group, newest era first
jq -r '.[] | select(.socials.telegram) | "\(.dates.likely_year) \(.name) → t.me/\(.socials.telegram[0])"' data/whitepapers.json | sort -r

# Find a person across the whole archive
jq -r '.[] | select(.people.team[]? | test("Terpin")) | .name' data/whitepapers.json
```

**Query the CSV** (spreadsheet / pandas):
```python
import pandas as pd
df = pd.read_csv("data/whitepapers.csv")
df[df.likely_year == 2017].sort_values("name")          # the 2017 cohort
df[df.wallets > 0][["name", "socials"]]                  # projects exposing wallets
```

## 🛠️ How the extraction works

Two small scripts, **no third-party Python packages** — just [`pdftotext`](https://poppler.freedesktop.org/) (Poppler) on your PATH.

| Script | Does |
|--------|------|
| [`tools/extract_metadata.py`](tools/extract_metadata.py) | Runs `pdftotext` on every PDF (caching text), then regex-extracts wallets, socials, dates, and role-confirmed names → `data/whitepapers.json` + `.csv` |
| [`tools/generate_index.py`](tools/generate_index.py) | Renders the JSON into the A–Z [`data/INDEX.md`](data/INDEX.md) and the stats in [`data/STATS.md`](data/STATS.md) |
| [`tools/build_site.py`](tools/build_site.py) | Builds the search site index (`search-index.json`) and commits per-paper plain text to [`text/`](text/) for GitHub-native full-text search |
| [`tools/search.py`](tools/search.py) | Offline full-text + metadata search CLI |

Re-run after adding PDFs:
```bash
python tools/extract_metadata.py     # mines every *.pdf (text cached in tools/.cache_txt/)
python tools/generate_index.py       # rebuilds INDEX.md + STATS.md
python tools/build_site.py           # rebuilds search index + text/
```

See [`data/SCHEMA.md`](data/SCHEMA.md) for the full data dictionary.

**Extraction logic in brief**
- **Wallets** — `0x`-prefixed 40-hex for ETH/EVM; `bc1…` bech32 and `1…/3…` base58 for Bitcoin (legacy addresses are kept only when bitcoin/wallet context words co-occur, to cut false positives).
- **Socials** — per-platform URL patterns; the first handle per platform is surfaced in the index, all of them in the JSON.
- **Dates** — full dates plus a `likely_year` = the most frequently cited plausible year in the document.
- **Team** — names that sit **immediately** next to a role keyword (`Jane Doe, CEO` / `CTO: John Roe`), with a heading/title-word stopword filter. This is the highest-precision signal; loose title-block "authors" are kept separately in the JSON.

## ⚠️ Accuracy & caveats

This is **best-effort, heuristic extraction** — not hand-curated ground truth. Be aware:

- **222 PDFs are scanned images** with no extractable text (`has_text: false`) — no metadata is mined from them. (OCR would fix this — see [Contributing](#-contributing).)
- **Wallet addresses may be examples, donation addresses, or citations**, not the project's official address. *Verify on-chain before trusting any address here.*
- **Name extraction is regex-based**, so expect occasional false positives (a title slipping through) and misses. Treat `people.team` as leads, not gospel.
- `likely_year` is a heuristic (most-cited year), which can be off when a paper cites a lot of history.

Found a wrong or missing value? **That's a great PR** — see below.
